AI Fluency case study

Using AI as a build partner without losing judgment.

A structured system for converting verified work into case studies, improving prompts through controlled iterations, curating honest visuals, and distinguishing workflows from agents.

A

Case framing

I replaced generic “AI project” language with a direct voice grounded in decisions, numbers, and limitations.

B

Prompt iteration

I improved one weak prompt across five controlled layers and compared how each layer changed the output.

C

Build workflow

I created an Intake → Draft → Critique → Revise → Format → Human Review pipeline and tested it on five real tasks.

Portfolio direction

The portfolio uses one claim: “I turn real business problems into practical machine learning solutions backed by measurable evidence.” The target audience is hiring managers recruiting Machine Learning interns or entry-level engineers, and the primary action is contacting me about an opportunity.

Identity and visual judgment

I created a restrained system using Inter, royal blue, near-black text, an off-white background, and one teal accent. Real captures are used whenever an asset is evidence, a person, a result, or a finished deliverable. Generated visuals are limited to connective tissue that makes no factual claim.

Prompt ladder

I started with a weak request to explain a FlyRank result, then added one layer at a time: clearer goal, defined audience, real context, output format, and verification requirements. The best version checked every claim, preserved the difference between precision and recall, and avoided unsupported model claims.

Reusable workflow

1

Intake

Extract the goal, audience, format, verified facts, and constraints.

2

Draft and critique

Create a first version, then identify missing evidence, vague claims, and audience problems.

3

Revise and verify

Apply selected changes and return a human-check list before publication.

The workflow was tested on an About paragraph, a case-study summary, an application answer, a LinkedIn post, and a recruiter email. The first five runs were estimated to save 36 minutes after setup, with larger savings on future reuse.

Workflow vs agent

The system is a workflow, not an agent, because the route is fixed in advance. To become an agent, the model would need control over tool choice, retrieval order, revision count, and stopping conditions. MCP could connect the system to private portfolio documents, but human approval would still be required before publishing metrics, links, or private information.

What this page proves

AI fluency is not only generating text quickly. It includes source discipline, controlled iteration, visual judgment, tool boundaries, honest documentation, and the ability to explain how the system works. This public site is the next step: the previous planning artifacts are now assembled into a reachable portfolio rather than remaining private documents.
